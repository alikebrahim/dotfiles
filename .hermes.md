# Dotfiles repository — agent directives

This file mirrors AGENTS.md for Hermes Agent compatibility.
Hermes loads .hermes.md from cwd and walks parents up to the git root.

## Git procedure

- Local git user: `dotfiles.agent <dotfiles.agent@axminet>` (configured via `git config --local`).
- Any changes made by the agent must be committed with a clear commit message and a descriptive/detailed commit body.
- Do NOT push unless the user explicitly asks.
- SSH config files are tracked in git; `authorized_keys` and `known_hosts` are ignored (operational state).
- Syncthing conflict files (`*.sync-conflict-*`) are also ignored.

## Non-negotiable rules

1. DO NOT make file/config changes unless the user explicitly requests the change.
2. DO NOT perform git operations (`add`, `commit`, `checkout`, `reset`, `clean`, `stash`, `mv`, `rm`, `pull`, `push`) unless explicitly requested.

## Sync model

- Syncthing propagates changes between hosts (not git pull). Verify sync completion before deploying.
- Git is the backup layer.
- Never create absolute symlinks in the repo — they break on other hosts.

## Stow deployment

- Deployment engine is `scripts/configure-host.sh` (tools, catalogued Stow, SSH overlay, system/user modules).
- `scripts/stow-host.sh` is a Stow-only compatibility wrapper around `configure-host.sh --scope stow`.
- Register new packages in `scripts/lib/stow-catalog.sh` and host/common profiles before apply.
- Run `bash ~/.dotfiles/scripts/configure-host.sh plan` then `apply` AFTER Syncthing sync completes, not before.
- Use `check` / `doctor` for pre-flight safety checks before any deployment.
- Explicit unstow: `configure-host prune --stow-package NAME` (double confirm). Never use `--adopt`.

## Tree folding — critical hazard

GNU Stow tree-folds when the target directory contains only content from one package.
Prevention already in place: `.stow-local-ignore`, safety dirs, `check-fold.sh`, configure-host fold checks.
If `~/.local` is a symlink, do NOT stow — fix the fold first.
